# 多矩阵节点服务器搭建方案（SM-UI Worker + Sing-box 原生多租户架构）

**核心定位**：基于 Cloudflare Workers + D1 无服务器控制面与 Sing-box 边缘节点的现代企业级多租户多 VPS 代理矩阵系统。  
**核心哲学**：主控零服务器成本 · 全球 Anycast 边缘高可用 · 节点 HTTP Pull 轮询免长连 · 订阅全协议秒级分发 · 节点高危端口零暴露 · 租户数据强隔离。  
**协议矩阵**：
* **VLESS + REALITY + Vision**（TCP 主力，首选 `443/TCP`，备选 `2096/TCP`，完美伪装主流 HTTPS 流量）
* **Hysteria 2**（UDP 极速爆发，首选 `443/UDP`，备选 `2096/UDP`，抗弱网 QoS 恶劣丢包）
* **Hysteria 2 端口跳跃 (Port Hopping / mport)**：Linux iptables NAT 转发 `22200-22300` 动态绕过 ISP UDP 限速。
* **单端口双协议复用**：单端口 `2096` 同时承载 TCP (Reality) 与 UDP (Hy2)，对外仅暴露一个业务端口，零端口浪费。

## 二、极简端口拓扑与云安全组规范

由于采用了 **HTTP Pull（节点主动拉取 Master）** 架构，VPS 节点**无需对外开放任何管理 API 端口**。

### 1. 云安全组放行矩阵（全节点统一）

| 规则名称 | 协议 | 端口范围 | 授权源 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **远程运维** | `TCP` | **22** | `0.0.0.0/0` (或堡垒机 IP) | 基础 SSH 运维管理 |
| **多协议业务复用** | **`TCP + UDP`** | **`2096`** | `0.0.0.0/0` | **TCP: VLESS Reality / UDP: Hysteria 2** |
| **Hy2 端口跳跃 (可选)** | **`UDP`** | **`22200:22300`** | `0.0.0.0/0` | **Hysteria 2 动态多端口跳跃范围** |

*注：`127.0.0.1:8080/TCP` 为 sing-box 的 `v2ray_api` 流量统计端口，由系统严格锁定在本地回环，严禁对外暴露。*

### 2. Hysteria 2 端口跳跃 iptables 配置（VPS 宿主机执行）

若需要突破运营商针对单 UDP 端口的 QoS 限速，可在宿主机执行以下 NAT 重定向：

```bash
# 将 22200 到 22300 范围内的 UDP 入站流量重定向至 2096
iptables -t nat -A PREROUTING -p udp --dport 22200:22300 -j REDIRECT --to-ports 2096

# 持久化规则（以 Ubuntu/Debian 为例）
apt-get install -y iptables-persistent
netfilter-persistent save
```

## 三、VPS 基础安全加固（全机必做）

在所有接入节点的机器上，必须清除云厂商后门及监控组件，并开启 BBR 加速：

### 1. 彻底卸载与隔离阿里云后门（Aegis / 云监控 / 云助手）

```bash
# 1. 停止并禁用官方服务
systemctl stop aegis 2>/dev/null || true
systemctl stop CmsGoAgent 2>/dev/null || true
systemctl stop aliyun-service 2>/dev/null || true
systemctl disable aegis CmsGoAgent aliyun-service 2>/dev/null || true

# 2. 卸载清除物理文件
rm -rf /usr/local/aegis /usr/local/cloudmonitor /usr/sbin/aliyun* /etc/systemd/system/aliyun.service

# 3. 配置持久化防火墙：硬丢弃云厂商上报回连 IP
cat << "EOF" > /etc/systemd/system/block-aegis.service
[Unit]
Description=Block Aliyun Aegis and Monitor Outbound
After=network.target

[Service]
Type=oneshot
ExecStart=/sbin/iptables -I OUTPUT -d 100.100.88.88 -j DROP ; /sbin/iptables -I OUTPUT -d 100.100.66.66 -j DROP
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now block-aegis.service
```

### 2. 启用 TCP BBR 拥塞控制算法

```bash
cat << "EOF" >> /etc/sysctl.conf
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
EOF

sysctl -p
# 验证：输出必须包含 bbr
sysctl net.ipv4.tcp_congestion_control
```

## 四、Master 主控部署指南（Cloudflare Workers + D1）

项目仓库：**`AkkunYo/sm-ui-worker`**（私有库安全托管）

### 1. 准备 Cloudflare D1 边缘数据库
1. 登录 Cloudflare 控制台 -> **Storage & Databases** -> **D1 SQL Database**。
2. 点击 **Create database**，名称填 **`sm-ui-db`**。
3. 进入 `sm-ui-db` -> **Console** 页面，粘贴执行项目根目录下的 `schema.sql` 完成表结构初始化。

### 2. 关联 Git 原生自动化构建与持续部署（推荐）
1. 在 Cloudflare 控制台 -> **Compute (Workers)** -> **Workers & Pages** -> 选择创建或关联已有 Worker `sm-ui-worker`。
2. 进入项目 **Settings** -> **Builds** -> 点击 **Connect to Git** 绑定 GitHub 仓库 `AkkunYo/sm-ui-worker`：
   * **Build command**：`npm run build`
   * **Deploy command**：`npx wrangler deploy`
   * **Root directory**：`/`
3. 进入 **Settings** -> **Bindings** -> 添加 D1 Database 绑定：
   * **Variable name**：`DB`
   * **D1 database**：选择 `sm-ui-db`
4. **绑定自定义域名（彻底绕过 GFW 对 workers.dev 的阻断）**：
   在 Worker 的 **Settings** -> **Triggers** -> **Custom Domains** 中添加自定义域名 `smui.zkyml.com`，Cloudflare 将自动配置边缘 SSL 并直连上线。
5. 首次访问 `https://smui.zkyml.com` 根据向导完成管理员密码初始化，随后可在「租户管理」建立租户账号（如 `zkyml`、`yjwenhua`）。

## 五、VPS 边缘节点接入（sm-node 容器化部署）

### 1. 节点关键依赖与构建规范
* **Sing-box 二进制构建标准**：必须固定版本 `v1.14.2` 且包含 `-tags with_v2ray_api` 标签，否则无法上报真实流量。
* **双自签证书自动就绪**：`sm-node` 启动时会自动在 `/var/lib/sm-ui/certs/` 检查并生成 `selfsigned.crt` 与 `hy2.crt` EC 椭圆曲线证书。
* **守护自愈看门狗**：节点守护进程每 30 秒自动巡检 `sing-box` 运行状态，意外退出秒级自动拉起。

### 2. Docker Compose 标准化部署流程（推荐）

在目标 VPS 的 `/opt/sm-node` 目录下创建 `docker-compose.yml`：

```yaml
services:
  sm-node:
    image: ghcr.io/akkunyo/sm-node:latest
    container_name: sm-node
    restart: always
    network_mode: "host"
    environment:
      - MASTER_URL=https://smui.zkyml.com
      - NODE_TOKEN=<从控制面板创建主机获得的专属 Token UUID>
    volumes:
      - ./data:/var/lib/sm-ui
```

启动容器：
```bash
cd /opt/sm-node && docker compose up -d
```

### 3. 验证节点连通性与服务日志
```bash
docker logs --tail 30 sm-node
```

成功标志：
```text

[Sync] Configuration applied successfully!
inbound/vless[vless-in]: tcp server started at [::]:2096
inbound/hysteria2[hy2-in]: udp server started at [::]:2096
v2ray-api: grpc server started at 127.0.0.1:8080
[Traffic] Captured deltas for 1 users from sing-box
```

### 2. 黄金测速 URL 与客户端规则规避
* **黄金测速地址**：系统统一采用 **`http://cp.cloudflare.com/generate_204`**。境内直连走 Cloudflare Anycast 国内节点直通，境外走就近，彻底消除 Google gstatic 超时红字。
* **避免本地 SSH 环路回流（TUN 模式关键避坑）**：
  在客户端（Clash/Mihomo）规则集顶层强制放行 22 端口，避免发往 VPS 的运维流量被代理自身回流阻断：
  ```yaml
  rules:
    - DST-PORT,22,DIRECT
    - GEOIP,LAN,DIRECT
    - GEOIP,CN,DIRECT
    - MATCH,PROXIES
  ```

## 七、生产实操排障与避坑指南

### 1. 报错：`v2ray api is not included in this build`
* **根因**：基础镜像内的 sing-box 二进制未携带 `with_v2ray_api` 标签。
* **解决**：在 Dockerfile 编译阶段强制注入 `-tags "with_quic,with_utls,with_clash_api,with_v2ray_api"` 重新编译静态二进制。

### 2. 报错：`read certificate: open ... selfsigned.crt: no such file or directory`
* **根因**：Worker 下发的配置指定了证书路径，但宿主机对应文件缺失。
* **解决**：`sm-node` 守护进程已内置 EC 自签证书生成器，启动时会自动在 `./data/certs/` 补齐 `selfsigned.crt` 与 `hy2.crt`。

### 3. 请求数激增与免费额度保护
* **心跳周期调优**：节点轮询周期严格设为 **30s**（每日 4 台机器仅消耗 11,520 次请求，占免费额度 11%）。
* **前端防挂机休眠**：Vue 控制台监听页面 `visibilitychange` 事件，切至后台或最小化自动销毁定时器停止发包，彻底杜绝配额泄漏。
